From NumPy arrays to PyTorch tensors

A neural network never sees a "photo" or a "review". It sees a block of numbers with a shape. Most bugs in deep learning code are shape bugs, so it pays to get fluent with shapes first.

Why not just Python lists?

What

A NumPy ndarray is a single block of memory holding numbers of one type (e.g. float32), plus metadata: its shape, dtype and strides.

How

A Python list is an array of pointers to separate Python objects scattered across memory. Adding two lists element by element runs the interpreter loop once per element. NumPy runs one compiled C loop over contiguous memory and can use SIMD CPU instructions that process several numbers per cycle.

Why

Deep learning means billions of multiply-adds. Vectorized operations are typically 10–100× faster than Python loops. Contiguous memory is also what lets PyTorch hand the same data to a GPU.

import numpy as np, time

n = 1_000_000
a_list, b_list = list(range(n)), list(range(n))
a_np,   b_np   = np.arange(n),   np.arange(n)

t = time.perf_counter(); c = [x + y for x, y in zip(a_list, b_list)]; t_list = time.perf_counter() - t
t = time.perf_counter(); c = a_np + b_np;                           t_np   = time.perf_counter() - t
print(f"list: {t_list*1000:.1f} ms   numpy: {t_np*1000:.1f} ms")

Run this in Colab. The exact numbers depend on the machine, but the gap is always large.

Rank and shape: scalars to 5D

A tensor is the general name for an n-dimensional array. Its rank (or ndim) is how many indices you need to reach one number. Its shape is the size along each axis.

Creating arrays and tensors

The two libraries have nearly identical APIs, so you can carry over most of what you know about NumPy.

import numpy as np
a = np.array([[1, 2], [3, 4]])
np.zeros((2, 3))
np.ones((2, 3))
np.random.rand(2, 3)   # U[0,1)
np.arange(12)          # 0..11
a.shape, a.dtype       # (2,2) int64
import torch
t = torch.tensor([[1, 2], [3, 4]])
torch.zeros((2, 3))
torch.ones((2, 3))
torch.rand((2, 3))     # U[0,1)
torch.arange(12)       # 0..11
t.shape, t.dtype       # torch.Size([2,2]) int64
dtype trapNumPy defaults to float64. PyTorch layers expect float32. torch.from_numpy(np_array) keeps float64, and the first nn.Linear then raises "expected scalar type Float but found Double". Fix it with .float() or np_array.astype(np.float32).

Indexing and slicing

What

Selecting parts of a tensor: x[row, col], ranges start:stop:step, and boolean masks.

How

Slices return a view, a new window onto the same memory, so nothing is copied. Boolean/“fancy” indexing returns a copy.

Why

You'll do this constantly: pick a batch, select a channel, crop an image (img[:, 4:28, 4:28]), or mask out padding tokens.

Try it · x = np.arange(24).reshape(4, 6)

Reshape, view, flatten, permute

What

Changing the shape without changing the data. 12 numbers can be (12,), (3,4), (2,2,3), and so on, as long as the product of the dimensions stays 12.

How

The memory stays the same flat list of numbers. Only the strides change. Strides tell PyTorch how many elements to jump to move one step along each axis. -1 means "infer this dimension".

Why

An MLP needs vectors, so a (64,1,28,28) batch of MNIST images must become (64,784). That's exactly what nn.Flatten() does in the course baseline.

Reshape playground · 24 numbers

x = torch.arange(12)
x.reshape(3, 4)       # works on any tensor; copies only if it must
x.view(3, 4)          # never copies, but needs contiguous memory
x.reshape(-1, 6)      # -1 is inferred → (2, 6)

imgs = torch.rand(64, 1, 28, 28)
imgs.flatten(start_dim=1).shape     # (64, 784), keeps the batch axis
imgs.permute(0, 2, 3, 1).shape      # NCHW → NHWC (for matplotlib)

x.reshape(3, 4).T.is_contiguous()   # False: transpose only swaps strides
# → .view() on it fails; use .reshape() or .contiguous().view()
Reshape ≠ transposereshape(4, 3) on a (3,4) matrix refills the rows in memory order. It does not swap rows and columns. Use .T / .permute() to reorder axes. Confusing the two silently scrambles images, and the shape still looks correct.

Broadcasting

What

Elementwise operations between tensors of different shapes, without writing loops or copying data.

How

Align the shapes from the right. Two dimensions are compatible if they're equal or one of them is 1. Size-1 axes (and missing axes) are virtually stretched to match.

Why

This is how a bias vector (10,) is added to every row of a (64,10) output, and how Normalize subtracts a per-channel mean (3,1,1) from a (3,32,32) image.

Broadcasting · a (3,1) + b (1,4) → (3,4)

Dashed cells are virtual copies; no extra memory is used. Hover a result cell to see which inputs produced it.

Matrix multiplication: the core operation

Elementwise * multiplies matching entries. Matrix multiplication @ (or torch.matmul) takes dot products of rows with columns. The inner dimensions must match: (n, k) @ (k, m) → (n, m).

x = torch.rand(64, 784)        # a batch of 64 flattened images
W = torch.rand(128, 784)       # weights of nn.Linear(784, 128)
b = torch.rand(128)
h = x @ W.T + b                # (64,784) @ (784,128) → (64,128), b broadcasts
# this line *is* nn.Linear: every MLP layer is one matmul + one broadcast add
Why GPUs matterOne matmul of (64,784)@(784,128) is about 6.4 million multiply-adds, and they're all independent. A GPU runs thousands of them in parallel. That's why model.to("cuda") and x.to("cuda") speed training up so much.

Cleaning and preprocessing

Before any model trains, the raw data goes through a fixed pipeline. Unlike augmentation, preprocessing is deterministic and is applied to both train and test data.

  1. Clean: drop or impute missing values, remove duplicates and corrupt files, fix inconsistent labels ("Positive" vs "positive").
  2. Encode: turn everything into numbers. Pixels already are; labels become integers 0…9; text becomes token IDs.
  3. Scale: put features on a comparable range so no single feature dominates the gradients.
  4. Shape: arrange into the layout the model expects ((N,784) for an MLP, (N,C,H,W) for a CNN).
  5. Split and batch: separate train / validation / test, then let a DataLoader shuffle and batch.

Why scale at all?

Gradient descent takes steps of the same learning rate in every direction. If one input lives in [0, 255] and another in [0, 1], the loss surface is a long, narrow valley. The optimizer zig-zags across it or diverges. Centering around 0 with unit variance makes the surface rounder, so training is faster and more stable. It also keeps the inputs to the first layer on the scale that PyTorch's default weight initialization assumes.

Data leakageCompute mean/std (and any imputation values) on the training set only, then apply them to the test set. Computing them on everything lets information about the test set leak into training and inflates your reported accuracy.
