05 · Theory

Why augmentation works

Flipping images and swapping words can look like a hack. It isn't. Augmentation has a clear theoretical basis: it reduces the gap between what a model learns from a finite dataset and how it performs on data it has never seen.

The generalization gap

We'd like to minimise the true risk: the expected loss over every input the model could ever meet. We can only compute the empirical risk on our n training examples:

R(f) = 𝔼(x,y)~𝒟 [ L(f(x), y) ]    vs    Remp(f) = 1⁄n Σi L(f(xi), yi)

Training drives R_emp down. The quantity that matters is R. The difference between them is the generalization gap, which you measure as train accuracy − test accuracy. Classical learning theory says the gap grows with model capacity and shrinks with dataset size n, roughly like √(capacity / n).

Overfitting

The model has enough capacity to memorise noise and quirks of the particular training examples. Training accuracy approaches 100% while test accuracy stalls. The MNIST MLP has 109,386 parameters and the baseline trains on 5,000 images, about 22 parameters per example. It has plenty of room to memorise.

There are three ways to shrink the gap:

  1. More real data (larger n). This is the best option, but it's expensive. The assignment's 5k → 50k sweep measures exactly this effect.
  2. Less effective capacity: smaller models, weight decay, dropout, early stopping.
  3. Better prior knowledge: tell the model what shouldn't matter. Augmentation does this, and in practice it also acts like option 1 at almost no cost.

Try this: at degree 9 with 0 copies, train error is near zero and the curve swings wildly between points (overfitting). Add copies and the fit smooths out and test error drops. Push σ to 0.3 and train error climbs: the augmentation is now strong enough to wash out real detail, and the model starts to underfit.

The theory behind the demoTraining on inputs with small added noise is approximately equivalent to adding a penalty on how steeply the function changes, a form of Tikhonov regularization (Bishop, 1995). Jittering inputs while keeping the label fixed tells the model that nearby inputs should get the same output. That's a smoothness prior, and it's the same prior every image and text augmentation encodes.

Augmentation encodes invariance

What

A function is invariant to a transformation T if f(T(x)) = f(x). A digit classifier should be invariant to small shifts, an animal classifier to horizontal flips, and a sentiment classifier to synonym swaps.

How

Augmentation replaces the training objective with its average over transformations:

Raug(f) = 1⁄n Σi 𝔼T~𝒯 [ L(f(T(xi)), yi) ]

Minimising this pushes f to give the same answer for every T(xᵢ), so the invariance is learned from data. Each T you include is a claim: "this change does not affect the label". If the claim is true, you've added free, correct information. If it's false (a horizontal flip on digits), you've added label noise.

Where the invariance comes fromExampleCost
Data (augmentation)MLP + random shifts learns shift toleranceMore training time; only approximate
Architecture (inductive bias)A CNN's shared convolution filters are shift-equivariant by constructionNeeds a suitable architecture; only covers that transformation

This is why augmentation matters more for an MLP than for a CNN. The MLP's architecture gives it no spatial priors, so every invariance has to come from the data.

Vicinal risk minimization

Empirical risk treats each training example as a single point (a delta function) and says nothing about the space between points. Vicinal Risk Minimization (Chapelle et al., 2000) replaces each point with a small neighbourhood (a vicinity distribution) and trains on samples from it:

Rvicinal(f) = 1⁄n Σi 𝔼(x̃, ỹ) ~ ν(· | xi, yi) [ L(f(x̃), ỹ) ]
  • Gaussian noise → the vicinity is a small ball around xᵢ, with the same label.
  • Flips, crops, synonyms → the vicinity is the set of semantically equivalent inputs, with the same label.
  • Mixup (Zhang et al., 2018) → the vicinity between two examples: x̃ = λxᵢ + (1−λ)xⱼ, ỹ = λyᵢ + (1−λ)yⱼ, with λ ~ Beta(α, α). This encourages the model to behave linearly between classes, which tends to give better-calibrated confidence.

Seen this way, augmentation is a principled way to fill the empty space around each training example with sensible labels.

Augmentation as a regularizer

What you'll observe

Training accuracy goes down (the task got harder, and memorisation no longer works). Test accuracy goes up, or holds steady. The gap shrinks.

Why that's good

Lower training accuracy here isn't a failure. It means the model is fitting signal, not noise. Judge augmentation by test accuracy and the gap, never by train accuracy alone.

Augmentation works alongside dropout and weight decay rather than replacing them. It has two practical side effects:

  • Training takes longer to converge, because the model sees a harder, ever-changing dataset. Five epochs may be enough without augmentation and not enough with it.
  • Augmented samples are correlated. Eight flips and crops of one dog are worth less than eight different dogs. The effective sample size grows, but by less than the raw count suggests. Expect 5k + augmentation to beat 5k, but usually not to match 50k real images.

Checklist: is this augmentation a good idea?

  1. Label-preserving? Would a human give T(x) the same label as x?
  2. Realistic? Could T(x) plausibly appear in the test set or in deployment?
  3. Covers a real weakness? Does the model or dataset lack this invariance (small data, no architectural prior)?
  4. Strength tuned? Start mild and increase until validation accuracy stops improving.
  5. Train only, after the split? Test data stays untouched.
