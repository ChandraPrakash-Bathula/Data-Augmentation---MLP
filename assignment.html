06 · Assignment

MLP scaling & data augmentation impact

Two experiments, one question: what improves generalization more, more real data or augmented data? You'll train the MNIST MLP at four dataset sizes, then train an MLP on CIFAR-10 with and without augmentation.

The plan

  1. Start from the baseline: the MLP in MNIST.ipynb trained on 5,000 samples.
  2. Scale the data: retrain with 10k, 30k and 50k training samples. The 10,000-image test set stays fixed.
  3. Augment CIFAR-10: train an MLP on CIFAR-10 with and without an augmentation pipeline.
  4. Plot train and test accuracy curves for every run.
  5. Reflect on what dataset size and augmentation each did to the generalization gap.

1 · Reusable setup

Write the training loop once as functions, so every experiment runs the same code and differs only in data. That's what makes the comparison fair.

import torch, torch.nn as nn, torch.optim as optim, random, numpy as np
from torchvision import datasets, transforms
from torch.utils.data import DataLoader, Subset

def set_seed(s=42):
    random.seed(s); np.random.seed(s); torch.manual_seed(s); torch.cuda.manual_seed_all(s)

device = "cuda" if torch.cuda.is_available() else "cpu"

class MLP(nn.Module):
    def __init__(self, in_dim=784, hidden=(128, 64), n_classes=10):
        super().__init__()
        layers, d = [nn.Flatten()], in_dim
        for h in hidden:
            layers += [nn.Linear(d, h), nn.ReLU()]; d = h
        layers.append(nn.Linear(d, n_classes))
        self.net = nn.Sequential(*layers)
    def forward(self, x):
        return self.net(x)

@torch.no_grad()
def accuracy(model, loader):
    model.eval(); correct = total = 0
    for x, y in loader:
        x, y = x.to(device), y.to(device)
        correct += (model(x).argmax(1) == y).sum().item(); total += y.size(0)
    model.train(); return correct / total

def train(model, train_loader, eval_train_loader, test_loader, epochs=10, lr=1e-3):
    model.to(device)
    opt, loss_fn = optim.Adam(model.parameters(), lr=lr), nn.CrossEntropyLoss()
    hist = {"train": [], "test": []}
    for ep in range(epochs):
        for x, y in train_loader:
            x, y = x.to(device), y.to(device)
            loss = loss_fn(model(x), y)
            opt.zero_grad(); loss.backward(); opt.step()
        hist["train"].append(accuracy(model, eval_train_loader))   # clean (un-augmented) train data
        hist["test"].append(accuracy(model, test_loader))
        print(f"epoch {ep+1:2d}  train {hist['train'][-1]:.3f}  test {hist['test'][-1]:.3f}")
    return hist
Why a separate eval_train_loader?With augmentation on, accuracy measured on augmented batches is lower simply because the inputs are harder. To compare the train-test gap fairly across runs, measure train accuracy on the clean training images using the test-time transform.

2 · MNIST scaling experiment

tf = transforms.Compose([transforms.ToTensor(), transforms.Normalize((0.5,), (0.5,))])
full_train = datasets.MNIST("./data", train=True,  download=True, transform=tf)
test_set   = datasets.MNIST("./data", train=False, download=True, transform=tf)   # fixed 10k
test_loader = DataLoader(test_set, batch_size=1000)

set_seed(42)
perm = torch.randperm(len(full_train))          # one shuffle → nested subsets (5k ⊂ 10k ⊂ 30k ⊂ 50k)

results = {}
for n in [5_000, 10_000, 30_000, 50_000]:
    set_seed(42)
    subset = Subset(full_train, perm[:n].tolist())
    train_loader = DataLoader(subset, batch_size=64, shuffle=True)
    eval_loader  = DataLoader(subset, batch_size=1000)
    print(f"\n=== n = {n} ===")
    results[n] = train(MLP(), train_loader, eval_loader, test_loader, epochs=10)
Design choices worth explaining in your notebook

Random, nested subsets: range(5000) takes the first 5k images, which may not be representative. A random permutation fixes that, and nesting means each larger set contains the smaller ones. Same seed per run: differences come from data, not luck. Same epochs: note that 50k samples gives 10× more gradient steps per epoch than 5k. Mention this as a confounder, or also compare at an equal number of steps.

3 · CIFAR-10 augmentation experiment

MEAN, STD = (0.4914, 0.4822, 0.4465), (0.2470, 0.2435, 0.2616)
plain_tf = transforms.Compose([transforms.ToTensor(), transforms.Normalize(MEAN, STD)])
aug_tf   = transforms.Compose([
    transforms.RandomCrop(32, padding=4),
    transforms.RandomHorizontalFlip(),
    transforms.ColorJitter(0.2, 0.2, 0.2),
    transforms.ToTensor(),
    transforms.Normalize(MEAN, STD),
])

test_c   = datasets.CIFAR10("./data", train=False, download=True, transform=plain_tf)
test_ld  = DataLoader(test_c, batch_size=1000)
clean_tr = datasets.CIFAR10("./data", train=True,  download=True, transform=plain_tf)
aug_tr   = datasets.CIFAR10("./data", train=True,  download=True, transform=aug_tf)

def cifar_mlp():   # 3*32*32 = 3072 inputs; a bit wider than the MNIST net
    return MLP(in_dim=3072, hidden=(512, 256), n_classes=10)

cifar = {}
for name, ds in [("no_aug", clean_tr), ("aug", aug_tr)]:
    set_seed(42)
    cifar[name] = train(cifar_mlp(),
                        DataLoader(ds, batch_size=128, shuffle=True, num_workers=2),
                        DataLoader(clean_tr, batch_size=1000),        # clean train accuracy
                        test_ld, epochs=20)
Optional, but it makes the strongest reportAugmentation helps most when data is scarce. Repeat the CIFAR comparison on a 10k subset of the training set (Subset(ds, idx) with the same idx for both runs). The difference between augmented and plain runs is usually clearer there than on the full 50k.

Remember the original-vs-augmented visualization as well. It's part of the image-augmentation activity, and it shows the reader what the model actually trained on.
