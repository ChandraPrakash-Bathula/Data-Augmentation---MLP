04 · Augmentation

Image augmentation

A flipped cat is still a cat. Image augmentation applies label-preserving transformations to training images, so a model sees thousands of plausible variations of each photo instead of one fixed version.

The idea in one picture

What

Random transformations such as flips, rotations, crops, colour changes, noise, and occlusion, applied to training images on the fly. Each epoch, every image is drawn with fresh random parameters.

How

In PyTorch you chain torchvision.transforms in a Compose and give it to the training Dataset. The DataLoader calls it every time an image is fetched, so no augmented images are ever saved to disk.

Why

Each transform encodes a fact you already know: "the class doesn't depend on left-vs-right, lighting, or exact position." Augmentation turns that knowledge into training data, so the model learns those invariances instead of memorising pixels.

Equivalent torchvision code

Geometric transforms

Horizontal flip: RandomHorizontalFlip(p=0.5)

What

Mirror left↔right: pixel (x, y) moves to (W−1−x, y).

How

With probability p the image is flipped, otherwise it's unchanged. p=0.5 means each epoch is a coin toss.

Why

Most natural scenes have no preferred left-right direction, so this doubles the effective dataset for free. It's the single most commonly used image augmentation. Don't use it for text, digits, or road signs that point in a direction.

Vertical flip: RandomVerticalFlip(p)

Why and when

Useful when "up" is arbitrary: satellite and aerial images, microscopy, histology slides. It's wrong for everyday photos, where an upside-down car or face is something the test set will never contain.

Rotation: RandomRotation(degrees=15)

What

Rotate by an angle θ drawn uniformly from [−degrees, +degrees].

How

Each output pixel looks up its source location through the inverse rotation [x', y'] = R(−θ)·[x − cₓ, y − c_y] + c. Those locations fall between pixels, so values are interpolated (nearest-neighbour by default, or bilinear). Corners outside the source are filled with fill=0 (black).

Why

Handwriting, phone photos and documents are rarely perfectly upright. Keep the angle small (10–20°): large angles create black corners the test set never has, and can change the class.

Random resized crop: RandomResizedCrop(size, scale=(0.08, 1.0), ratio=(3/4, 4/3))

What

Take a random rectangle covering a fraction scale of the image area, with aspect ratio in ratio, then resize it to size.

How

Area A = U(scale)·W·H, ratio r log-uniform, crop width √(A·r) and height √(A/r) at a random position. This teaches robustness to scale as well as position.

Why

Objects aren't always centred or the same size. The default scale=(0.08,1) is designed for 224-px ImageNet images. For 32×32 CIFAR-10 an 8% crop is only 9×9 pixels and the object is usually gone. That's why CIFAR uses the gentler RandomCrop(32, padding=4): pad 4 px on every side, then crop back to 32, which shifts the image by up to ±4 px.

Photometric (colour) transforms

Colour jitter: ColorJitter(brightness, contrast, saturation, hue)

ParameterRandom factorPer-pixel operation
brightness = bf ∈ [1−b, 1+b]p' = f · p
contrast = cf ∈ [1−c, 1+c]p' = m + f · (p − m), where m = mean grey level of the image
saturation = sf ∈ [1−s, 1+s]p' = g + f · (p − g), where g = this pixel's grey value
hue = h (≤ 0.5)δ ∈ [−h, h]rotate the hue angle by δ × 360° in HSV space
Why

The same object photographed indoors, outdoors, at dusk or by a different camera produces very different pixel values. Jitter makes the model rely on shape and texture instead of exact colour. Keep hue small: if colour defines the class (ripe vs unripe fruit, traffic lights, some flower species), large hue shifts produce mislabelled data.

Noise, blur and occlusion

TransformWhat it doesSimulates / teaches
Gaussian noisex' = clip(x + ε), ε ~ N(0, σ²) per pixel (no built-in transform; add it as a lambda after ToTensor)Sensor noise and low light. Stops the model from depending on exact pixel values.
GaussianBlur(kernel_size, sigma)Convolve with a Gaussian kernel, so each pixel becomes a weighted average of its neighboursDefocus, motion and low resolution. Pushes the model towards coarse shape rather than fine texture.
RandomErasing(p, scale) (Cutout)Blank out a random rectangle. Runs on tensors, so it goes after ToTensor.Occlusion. The model must use several parts of the object, not just one shortcut feature.

import torch
from torchvision import transforms

add_noise = transforms.Lambda(lambda x: (x + 0.05 * torch.randn_like(x)).clamp(0, 1))

tfm = transforms.Compose([
    transforms.ToTensor(),
    add_noise,                                         # σ = 0.05 on the [0,1] scale
    transforms.GaussianBlur(kernel_size=5, sigma=(0.1, 2.0)),
    transforms.RandomErasing(p=0.5, scale=(0.02, 0.2)),
])

Where augmentation goes in the pipeline

Three rules
  1. Train only. The test set measures performance on real data, so it gets only deterministic preprocessing (ToTensor, Normalize).
  2. On the fly, not pre-generated. Each epoch sees new random variants, so the effective dataset is effectively unlimited and disk use stays the same.
  3. Order matters. PIL-based transforms (crop, flip, jitter) go first, then ToTensor(), then Normalize. Tensor-only transforms like RandomErasing go after ToTensor.
from torchvision import datasets, transforms
from torch.utils.data import DataLoader

MEAN, STD = (0.4914, 0.4822, 0.4465), (0.2470, 0.2435, 0.2616)

train_tf = transforms.Compose([
    transforms.RandomCrop(32, padding=4),       # random shift up to ±4 px
    transforms.RandomHorizontalFlip(),          # p = 0.5
    transforms.ColorJitter(0.2, 0.2, 0.2),      # mild lighting changes
    transforms.ToTensor(),
    transforms.Normalize(MEAN, STD),
])
test_tf = transforms.Compose([                  # no randomness at test time
    transforms.ToTensor(),
    transforms.Normalize(MEAN, STD),
])

train_ds = datasets.CIFAR10("./data", train=True,  download=True, transform=train_tf)
test_ds  = datasets.CIFAR10("./data", train=False, download=True, transform=test_tf)
train_loader = DataLoader(train_ds, batch_size=128, shuffle=True, num_workers=2)
test_loader  = DataLoader(test_ds,  batch_size=256)

Visualizing original vs augmented (activity deliverable)

To plot tensors you have to undo Normalize and move channels last, from (C,H,W) to (H,W,C):

import matplotlib.pyplot as plt
import torch

raw = datasets.CIFAR10("./data", train=True, download=True)        # PIL images, no transform
classes = raw.classes

def show(t):                                    # t: normalized (3,32,32) tensor
    t = t * torch.tensor(STD)[:, None, None] + torch.tensor(MEAN)[:, None, None]
    return t.clamp(0, 1).permute(1, 2, 0).numpy()

fig, axes = plt.subplots(4, 6, figsize=(10, 7))
for row in range(4):
    img, label = raw[row]
    axes[row, 0].imshow(img); axes[row, 0].set_title(f"original\n{classes[label]}", fontsize=8)
    for col in range(1, 6):
        axes[row, col].imshow(show(train_tf(img)))   # same image, new random draw
        axes[row, col].set_title(f"aug #{col}", fontsize=8)
for ax in axes.flat: ax.axis("off")
plt.tight_layout(); plt.show()
