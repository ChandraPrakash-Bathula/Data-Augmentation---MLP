From one perceptron to a multi-layer perceptron

The MNIST baseline in MNIST.ipynb is only about 15 lines of PyTorch. This page walks through what each line does and why the architecture looks the way it does.

The perceptron: one neuron

What

A perceptron (Rosenblatt, 1958) takes inputs x₁…xₙ, multiplies each by a weight, adds a bias, and fires if the total crosses zero: ŷ = step(w·x + b).

How

Geometrically, w·x + b = 0 is a straight line (a hyperplane in higher dimensions). Points on one side are class 1 and points on the other side are class 0. Learning means moving that line.

Why it's not enough

A single line can only separate linearly separable data. The classic counterexample is XOR: no single straight line splits {(0,1),(1,0)} from {(0,0),(1,1)}.

Why stacking needs a non-linearity

The fix for XOR is to stack neurons in layers. But stacking linear layers alone gains nothing, because two linear maps compose into one linear map:

h = W1 @ x + b1
y = W2 @ h + b2  =  (W2 @ W1) @ x + (W2 @ b1 + b2)  =  W' @ x + b'   # still one straight line

Put a non-linear activation function between the layers and that collapse can't happen. With enough hidden units, an MLP can approximate any continuous function on a bounded region. This is the Universal Approximation Theorem.

Activation functions and why ReLU won

Activation explorer

FunctionFormulaMax derivativeTrade-off
Sigmoid1 / (1 + e⁻ˣ)0.25Saturates at both ends. Gradients shrink layer after layer (vanishing gradient).
Tanh(eˣ − e⁻ˣ)/(eˣ + e⁻ˣ)1.0Zero-centred, which helps, but still saturates.
ReLUmax(0, x)1.0Gradient is exactly 1 for positive inputs, so it doesn't vanish. Very cheap to compute. Units can "die" if they're always negative.
Why ReLU, concretely

Backprop multiplies one derivative per layer. With sigmoid, ten layers multiply at most 0.25¹⁰ ≈ 0.000001, so the early layers barely learn. With ReLU, active paths multiply by 1¹⁰ = 1. That property is a big reason deep networks became trainable after about 2011.

The MNIST MLP, layer by layer

class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.flatten = nn.Flatten()
        self.fc1 = nn.Linear(28*28, 128)
        self.fc2 = nn.Linear(128, 64)
        self.fc3 = nn.Linear(64, 10)
        self.relu = nn.ReLU()

    def forward(self, x):
        x = self.flatten(x)          # (B,1,28,28) → (B,784)
        x = self.relu(self.fc1(x))   # (B,784)     → (B,128)
        x = self.relu(self.fc2(x))   # (B,128)     → (B,64)
        return self.fc3(x)           # (B,64)      → (B,10) raw scores ("logits")

This is why MLPs scale poorly on images, and why augmentation matters more when the parameter count is large compared with the amount of data.

Logits, softmax and cross-entropy

What

The last layer outputs 10 unbounded scores (logits). Softmax turns them into probabilities: pᵢ = eᶻⁱ / Σⱼ eᶻʲ. Cross-entropy is −log(p_true), so the loss is low when the correct class gets high probability.

How

nn.CrossEntropyLoss applies log-softmax and the loss in one numerically stable step. That's why the model has no softmax at the end. Adding one would apply it twice.

Why

Cross-entropy punishes confident mistakes severely. Probability 0.01 on the true class costs −log(0.01) = 4.6, while 0.5 costs only 0.69. That gives strong gradients exactly where the model is most wrong.

One training step, five lines

criterion = nn.CrossEntropyLoss()
optimizer = optim.Adam(model.parameters(), lr=0.001)

for epoch in range(5):
    for images, labels in train_loader:      # 5000 / 64 → 79 batches per epoch
        outputs = model(images)              # 1. forward pass → logits
        loss = criterion(outputs, labels)    # 2. how wrong are we?
        optimizer.zero_grad()                # 3. clear old gradients (they accumulate!)
        loss.backward()                      # 4. backprop: ∂loss/∂w for all 109,386 w
        optimizer.step()                     # 5. w ← w − lr · (adaptive) gradient

Evaluating properly

The notebook checks 10 test images by eye. For the assignment you need accuracy over the full 10,000-image test set, computed the same way every time:

def accuracy(model, loader):
    model.eval()                      # switches off dropout/batch-norm training behaviour
    correct = total = 0
    with torch.no_grad():             # no graph → faster, less memory
        for x, y in loader:
            correct += (model(x).argmax(1) == y).sum().item()
            total   += y.size(0)
    model.train()
    return correct / total
Track both numbersCompute accuracy on the training set and on the test set after every epoch. The gap between them is your overfitting meter, and it's the main quantity the assignment asks you to explain.

What an MLP can't see

nn.Flatten() discards the 2D layout. To an MLP, pixel (5,5) and pixel (5,6) are just inputs #145 and #146. It has no built-in idea that they're neighbours. Two consequences:

  • If you shuffle the pixel order of every image with one fixed permutation, an MLP trains to the same accuracy. A CNN would not.
  • A digit shifted 2 pixels to the right activates a completely different set of weights. The MLP has to learn shift tolerance from examples. Augmentation supplies those examples.

That last point is the bridge to the rest of this week. Augmentation is how we teach a model invariances that its architecture doesn't provide.
